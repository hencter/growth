# Builder-Verifiability（建造者可验证性）

> **这是谁的想法**：学习者在回答拷问 Q1（备选方案）时自己说出来的（2026-10-05）。本页做两件事：**把他的话固化**，以及**把它与他第 2 条回答合成一个模型**——合成部分是我的，已明确标注。

## 一、学习者的原话（未加工）

> 「我比较过，Python 生态很好，但其**缩进语法对 AI 并不友好**，因为它**难以判断代码层级**。加上 Python 是**解释型语言**，会产生**大量冗余文件**。而使用 Rust 时，无论是编写测试还是编译完整系统，其**报错信息都能让 AI 清晰感知**。AI 可以通过 **warning 或异常抛出，明确下一步操作**，这就是我选择 Rust 的理由，未来也不太可能推翻这一决定。」

## 二、定义（三句话）

1. **建造者可验证性（builder-verifiability）** = 一个技术栈让**建造者**（当建造者是 AI 代理时）能多快、多明确地知道「我错了、错在哪、下一步做什么」。
2. 它由三样东西决定：**结构是否显式**（能否无歧义地判断层级与边界）· **错误信号的质量**（编译期/静态 vs 运行期/静默）· **产物的信息密度**（是否产生大量需要代理额外阅读的冗余文件）。
3. 它是一条**架构成本属性**：信号差 → 代理多猜、多试、多读 → **token 与重试次数上升**。所以它在成本敏感的 AI 建造流程里，和性能、内存是同一层级的东西。

## 三、为什么它是「架构属性」，不是「工具偏好」

| 判据 | 说明 |
|---|---|
| 影响全局 | 它决定**每一行代码**的编写—验证循环，而不只是某模块 |
| 改动代价高 | 换语言/换栈等于重写；一旦定下就压在后续所有工作上 |
| 可权衡 | 拿它换生态成熟度（Rust 生态差 vs 信号强），是典型取舍 |
| 可度量 | 能落到数字：**agent 每次修复的平均 token**、**首次通过率**、**平均重试次数** |

架构属性的标准是「改了很贵、影响全局、可权衡」，它四条全中。

## 四、与他的第 2 条回答合成（**这是我的合成，标注为推断**）

学员两条回答合起来其实是一个模型：

```text
选择信号强的工具链（Rust）
      ↓ 降低
每次修改的猜测与重试次数
      ↓ 降低
每个用户动作的边际 token 成本
      ↓ 在用户量增长时
成本曲线斜率更平缓（第 2 条回答的"先坏"正是这条曲线）
```

也就是说：**他第 1 条回答不是"性能选择"，而是"成本选择"的上游** —— 用**开发期**的信号质量，换**运行期/规模化**的 token 成本。这与他的第 2 条回答（成本才是先坏的）**同一个逻辑闭合**。

## 五、何时不成立（边界，必须写清才不是口号）

- **当建造者是人时**：人类能靠经验补隐式结构的歧义，缩进的"信息量低"对人类的影响远小于对代理；
- **当代理能力提升到能可靠推断隐式结构时**（例如长上下文 + 结构感知解析稳定）：这条属性的权重会下降；
- **当写代码的量很小、运行量很大时**：运行期性能重新成为主导（此时信号质量退居次位）；
- **当生态缺件导致必须自研核心能力时**：生态成本可能反超信号收益——**这正是他 Context 里已经承认的代价**。

## 六、映射到已有概念（不冒充新理论）

- **可测试性 / 可验证性（testability / verifiability）**：已有质量属性家族；本条是它在「建造者非人」条件下的**特化**。
- **反馈延迟（feedback latency）**：编译期错误把反馈前移到编辑阶段，缩短了循环。
- **上下文经济（context economics）**：冗余文件 = 上下文税；这也解释了"解释型产生大量冗余文件"为何是架构级问题而不是洁癖。

## 补充：它买到什么、买不到什么（2026-10-05，学习者提出）

**买到**：把缺陷**左移**——编译期失败最便宜，线上事故最贵。指标链：**编译期捕获数 → CI 失败率 → 线上事故数 / 回滚次数 / MTTR**。

**买不到**：可判定类以外的错误——业务语义、需求理解、算法逻辑、跨服务一致性，以及一切"编译通过但行为错"的东西。**它抬的是下限，不是上限。**

所以：「**用 Rust 就不会有错误代码**」是不可辩护的绝对断言；可辩护的说法是「**编译期能挡住整整一类缺陷，显著降低线上事故概率**」。
## 补充：它其实是两个维度，而且互相拉扯（2026-10-05，学习者提出）

学习者在给出推翻条件时说：「产品迭代需要非常快速时，TypeScript 的优势可验证——**Rust 的短板是需要反复完整编译**」。这句话指出了本概念内部的张力：

| 维度 | 含义 | Rust | TypeScript |
|---|---|---|---|
| **信号质量** | 错误说得多清楚、多早 | 高（编译期、穷尽匹配） | 中（类型编译后消失，运行期信号弱） |
| **循环时延** | 每次验证要等多久 | 高（完整编译） | 低（增量、即时反馈） |

**决策规则**：约束在**正确性**侧 → 选高信号；约束在**迭代速度**侧 → 选低时延；两者都要 → **①先做便宜的缓解**（缩小编译范围：`cargo check` 只做类型检查、workspace 拆分、增量编译——通行实践，可自行验证）；**②再考虑异构**（核心 Rust + 迭代面 TS）。**换语言是最后手段，不是第一反应。**

**这也解释了「AI 原生语言」为何是有效的推翻条件**：若它能同时给出高信号 + 低时延，张力就消失了——学习者已把它写进 ADR 的推翻条件。

## 中文速览

- **建造者可验证性**：技术栈让**建造者（AI 代理）**多快、多明确地知道「我错了、错在哪、下一步做什么」。
- 三要素：**结构是否显式**（缩进层级对代理不友好）· **错误信号质量**（编译期报错/警告 vs 运行期静默）· **产物信息密度**（冗余文件=上下文税）。
- 为什么算架构属性：影响全局、改动代价高、可权衡、**可度量**（每次修复平均 token / 首次通过率 / 平均重试次数）。
- **与成本模型闭环**：信号强 → 少猜少试 → 边际 token 降 → 用户量增长时成本曲线更平（正是他说的"先坏"）。
- **边界**：建造者是人时权重下降 · 代理能可靠推断隐式结构时权重下降 · 运行量远大于编写量时性能重新主导 · 生态缺件到必须自研时可能反超。
